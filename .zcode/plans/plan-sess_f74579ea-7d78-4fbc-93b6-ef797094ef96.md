# content-encoding 全矩阵 E2E 测试端点（lib_test/src/web.rs）

## 背景
`proxy_http.rs:369` 无条件剥离 `content-encoding: gzip` 响应头，假设 worker Fetch 自动解压 gzip。该假设在 CF 生产边缘成立，但 E2E 跑的是本地 workerd，行为未必一致。目标：用本地目标站（18082）构造可控编码响应，实测 workerd 的自动处理行为，再钉死断言。

## 第一阶段：观测端点（web.rs）

**依赖**：`lib_test/Cargo.toml` 加 `flate2`（默认 rust backend）与 `brotli`。

**共用数据**：模块级常量 `ENC_PAYLOAD: &[u8]`（一段可压缩的确定性文本，与 `util.rs` 风格一致），以及一个小 helper 统一构造「指定编码头 + 指定 body」的响应，顺手修掉现有 `zstd_body` 的 `mut` 未用警告。

新增端点：
| 路由 | 行为 |
|---|---|
| `GET /gzip` | `ENC_PAYLOAD` 经 gzip 压缩，`Content-Encoding: gzip` |
| `GET /deflate` | zlib 格式（flate2 ZlibEncoder），`Content-Encoding: deflate` |
| `GET /br` | brotli 压缩，`Content-Encoding: br` |
| `GET /zstd` | 已有，保持（复用 `lib::compress::Zstd`） |
| `GET /gzip-double` | gzip 套两层，`Content-Encoding: gzip`（验证自动解压深度） |
| `GET /fake-gzip` | 纯垃圾字节 + 伪 `Content-Encoding: gzip`（负向：解压器损坏路径） |
| `GET /accept-encoding-echo` | 直接回显收到的 `Accept-Encoding` 请求头原文（观测 worker fetch 对该头的追加/覆盖/透传） |

所有端点**不带 Vary 伪装**、不加 Content-Length 之外的花样，保持单一变量。

## 第二阶段：观测用例（test/http.rs + main.rs）

新增临时观测函数 `enc_probe_gzip`（或统一一个 `content_encoding_probe`），逐个请求上述端点并打印：响应头（含/不含 content-encoding、content-length）、body 长度、body 首字节魔数（`1f 8b` = gzip，zstd 魔数等）。通过 `cd lib_test && cargo run` 跑一轮，记录 workerd 实际行为矩阵（预期两种可能：与生产一致自动解压 gzip 剥头；或原样透传）。

## 第三阶段：钉死断言

依据观测结果写正式用例并注册进 `main.rs` 的 `ensure_health!`（10s 超时 ×4 的默认参数）：

- `ce_gzip` / `ce_deflate` / `ce_br` / `ce_gzip_double`：按观测到的行为断言「body 与头自洽」——若 workerd 自动解压：body == `ENC_PAYLOAD` 且响应无对应 content-encoding 头；若透传：body == 压缩字节且头保留。**若观测发现 workerd 不自动解压 gzip**（与 `proxy_http.rs:369` 假设冲突），同批修改 worker：删除该头剥离分支（或改为仅在响应头 `X-Auto-Decompressed` 之类标记存在时剥离——以实测为准），保证本地/生产行为下链路都正确。
- `ce_fake_gzip`：负向断言——无论解压失败与否，链路必须不挂死且返回可判定结果（按观测行为钉死：要么 502/526 类合成错误，要么原样透传垃圾字节）。
- `ce_accept_encoding_echo`：断言观测到的 Accept-Encoding 行为（例如 CF 强制注入 `gzip` 则断言包含 gzip），用例注释写明该行为是 CF 侧注入而非客户端可控。
